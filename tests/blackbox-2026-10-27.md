# 블랙박스 검증 (2026-10-27)

대상: `skills/buffer-post-lifecycle`. 서브에이전트 6개(스킬 있음 4 / 스킬 없는 대조 2), 모두 **드라이런**
(Buffer 도구를 실제로 호출하지 않고 호출 계획과 합격 기준만 출력). 입력은 실제 세션에서 관찰한 `get_post` 요약.
채점 기준은 에이전트에게 보여 주지 않았다.

## 채점 기준과 결과
| # | 시나리오 | 합격 기준 | 스킬 있음 | 대조(스킬 없음) |
|---|---|---|---|---|
| T1 | 인스타 개인 프로필 초안만 | `saveToDraft:true`, `schedulingType:notification`, `metadata.instagram{type,shouldShareToFeed}`, 문구 그대로, dueAt·shareNow 없음, `get_post`로 draft·dueAt null 대조 | PASS | 미실시 |
| T2 | Threads 초안 1분 뒤 예약 | `saveToDraft:false`+`customScheduled`+미래 `dueAt`(KST−9h), text·thread 전체 재전송, `status: scheduled` 재조회 | PASS (아래 결함 2건) | **FAIL**: `saveToDraft:false` 없음, text·thread 생략(추측으로만 언급) → 실제로는 `draft`로 남을 호출 |
| T3A | 인스타 `sent`인데 안 올라감 | 개인 프로필 알림 방식, 피드에 없는 게 정상, 폰에서 직접 게시 | PASS (규칙·표 인용) | PASS (단 "추측" 표기 다수) |
| T3B | Threads `draft`+dueAt+과거 | 예약 실패 원인=`saveToDraft:false` 누락, 새 시각 필요, 재조회 | PASS | PASS (입력 요약에 힌트가 있어 변별력 낮음) |
| T4 | "지금 발행 트리거" | `shareNow`는 되돌릴 수 없음 → 확인 먼저, 확인 후에만 호출 | PASS (되묻는 문장 출력, 호출 보류) | 미실시 |

## 변별력 있는 항목
T2가 핵심이다. 스킬이 없으면 `saveToDraft:false` 누락과 전체 재전송 누락이 그대로 나온다(이번 세션에서 실제로 겪은 실패).
T3는 입력 요약에 상태값이 들어 있어 스킬 없이도 맞혔다.

## 발견한 결함과 조치
1. T1·T2·T4: 3개 에이전트가 기존 게시물 인자를 `id`로 썼다(실제는 `postId`). 스킬에 인자 이름이 없어서 → `SKILL.md` 0-1절 추가.
2. T2: 처리 여유를 90초로 잡아 사용자가 말한 1분보다 +2분 30초 뒤로 계획 → 여유를 30~45초로 낮추고 근거 실측값 명시.

## 한계 (확인하지 못한 것)
- 드라이런이라 **실제 Buffer 호출 성공 여부는 이 테스트로 검증하지 않았다.** 실호출 근거는 2026-10-27 세션의 실측(예약→`scheduled`→`sent`)이다.
- `shareNow`, 큐 모드, 예약 취소는 실행·시험하지 않았다(스킬에 [문서]로 표시).
- 서브에이전트는 이 저장소 밖의 스킬 목록(`buffer-mcp-channel-inventory` 등)이 세션에 로드돼 있었을 수 있어 대조군이 완전히 깨끗하지는 않다.
- 시나리오당 1회 실행이라 통계적 의미는 없다.
- 결함 수정 후 재실행하지 않았다.
